# 📅 Дневник переноса бота с голого Python на aiogram

Тут я буду описывать шаги перехода на aiogram, почему использовал то или иное решение при разработке. Постараюсь без лишней воды.

---

## 📈 Текущий статус проекта
* **Стек:** Python 3.14 + aiogram v3 + PostgreSQL + asyncpg + Docker + Makefile + async-pytest + httpx
* **Линтеры и форматеры:** ruff + black
* **Инфраструктура:** Локальный Docker-контейнер для БД, деплой на VPS (1 CPU, 2GB RAM, NVMe) через Docker Hub, GitHub Actions CI/CD.

    * Добавил в `requirements.txt` переменные окружения.
    * Через install.sh установил виртуальное окружение и нужные переменные.
    * **Измение кодовой базы:**
        * **bot/main.py:** 
            * Переписана логика на работу с диспатчером, роутерами и мидлвейрами.
            * Добавлено хранилише БД из `StoragePostgres`, которое взаимодествует с `Middleware`.
            * Добавлены роутеры взаимодействия с ботом.
        * **bot/states/order.py:**
            * Слой содержит в себе состояния, хранящиеся в FMS.
        * **bot/middlewares/db_middleware.py:**
            * Связующий слой кода и БД. 
            * Тут на данный момент вытаскивается `telegram_id` пользователя из любого события.
            * Сохраняет в БД его ID. 
            * В конце передает хранилище БД в хендлеры и передает контроль следующему хендлеру.
        * **bot/keyboards/pizza_kb:**
            * Слой содержит в себе необходимые клавиатуры для ботов. Является по своей сути "фермой" генерации `ключ:значение` для последующей интеграции с `callback'ами` хендлеров.
            * Ключ прописывается в `prefix="ключ"`, значение в `callback_data=...(name="значение")`.
            * Через `builder.adjust()` генерируется расопложение клавиш.
            * В конце возвращается `builder.as_markup()` содержащий клавиатуру.
        * **bot/handlers/init.py:**
            * Удалены все строки содержащие старые хендлеры, т.к приводит к конфлитку при исполнении кода.
        * **bot/handlers/message_start.py:**
            * Хендлер реализует нажатие команды `/start` и `callback'a` при отмене заказа.
            * Реализовано очистка состояния через `state.clear()`.
            * Реализовано указание состояние через импортированные модуль OrderState `state.set_state(OrderState.wait_for_pizza_name)`.
            * Вывод стартового сообщения.
            * При `callback` узнаем состояние клиента.
            * Происходит очистка состояния и указание нового состояния как при `/start`.
            * Фильтрация обработки `callback'а` при нажатии отмены заказа и в других случаях.
        * **bot/handlers/pizza_size.py:**
            * Хендлер реализует следующее состояние пользователя при выборе пиццы через ферму `ключ: значение`.
            * Устанавливает декоратор роутера принимающего callback_query с состоянием предыдущим пользователя и ключами из фермы: `@router.callback_query(OrderState.wait_for_pizza_name, PizzaMenuCallback.filter())`.
            * Создаем карту названий пиццы для более простого получения данных о выборе в `name_mapping` и `pizza_name = name_mapping.get(callback_data.name, "Не выбрана")`.
            * Так же обновляем состояние пользователя и выводим клавиатуру.
